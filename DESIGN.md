# Egg Mama — design contract

The product spec is `SPEC.md` (requirement IDs VIEW-1, INPUT-1, FLOCK-1, … are quoted below). This file is the
engineering contract that lets many people build modules in parallel and have them fit. **Read `SPEC.md` first.**

## 0. Pillars (why the old build failed and what we do instead)

The old build was a *website that contained a game*: masthead, score header, button footer, page scroll. This one is a
*game that happens to run in a browser*:

* **One fixed, full-viewport stage.** `html, body` are locked (no scrolling, no bounce, no pull-to-refresh, no
  zoom). A single `<canvas>` fills the visual viewport. Everything — world, HUD, captions — is drawn into that canvas or
  layered *inside the same stage* as DOM overlays (menus). Nothing ever resizes or moves the canvas.
* **Landscape phone first.** Fixed world height (360 u). Wider screens show more world sideways, never more vertically.
* **Touch first.** Swipe up = jump, left = brake/back up, right = push ahead. One swipe = one action.
* **Backgrounds are the only pixel art.** The 13 `docs/assets/*.webp` paintings are drawn crisp (smoothing off).
  Everything the player touches is smooth vector art drawn in code (no image assets for objects).
* **Everything deterministic.** Level = f(journeySeed, circuit, chapter). Sim = f(level, inputs).
* **No build step, no dependencies, no network calls while playing.** Plain ES modules in `docs/` (GitHub Pages serves
  `docs/` from `main`). Works offline after first load (service worker). All relative URLs (served from a repo subpath).

## 2. Units, view and camera

* World unit `u`; y DOWN. `T.viewH = 360` always visible vertically. Ground baseline `T.groundY = 292`. Nothing the
  player must do happens above y = 40. No vertical camera movement at all (the horizon stays steady in a jump).
* Screen mapping (render.mjs): `scale = cssH / 360` (CSS px per u) normally; if `cssW / scale < T.viewMinW (560)` use
  `scale = cssW / 560` and show extra sky above (world bottom stays anchored to the bottom edge). Visible world width
  is `cssW / scale` (≈ 640 on 16:9, ≈ 780 on 19.5:9). Draw the canvas at `dpr` (cap 3, cap pixels ≈ 3.6 M).
* Camera x: Mama at `T.mamaScreenX` (30 %) of the width, plus a little lead while pushing, smoothed; clamped to the
  chapter (`start.x - 120 … endX + 260`). Snap on chapter start/respawn. Camera never leads a jump differently.
* Safe areas: `insets {top,right,bottom,left}` in CSS px (from `env(safe-area-inset-*)`). Scenery draws to the full
  canvas edges; anything the player must tap or read (pause button, captions, egg pill) stays inside the insets.

## 3. Simulation (`sim.mjs` — already written; read its header)

`createGame(level, carry, {checkpoint})`, `startRun`, `easeIn` (after pause/rotation), `act(game,'jump'|'brake'|'push')`,
`step(game, {left,right})` at fixed `T.step = 1/120`, `drainEvents`, `respawn`, `snapshotCarry`, `cloneGame`,
and pure helpers `platformPosAt`, `enemyPosAt`, `hazardActive`, `hazardWarn`. Runtime state the renderer reads:
`game.mama {x,y,px,py,vx,vy,onGround,face,phase,squash,hurtT,invuln,…}`, `game.followers[]`, `game.platforms[]`
(`cx,cy` current top-left; `state` idle|rumble|fall for crumble), `game.pickups[]` (`taken`), `game.enemies[]`
(`x,y,face,defeated,defeatT`), `game.springs[]` (`bounceT`), `game.shield`, `game.magnet`, `game.flock`, `game.eggs`,
`game.score`, `game.checkpoint`, `game.status` (`ready|running|dead|exit|beacon`), `game.statusT`, `game.t`.
Interpolate drawing with `alpha` between `px,py` and `x,y` (and followers' `px,py`). Evaluate moving things at
`t - (1-alpha)*T.step` using `platformPosAt/enemyPosAt` or just use `cx,cy,x,y` (crumbles use `cy`).

If you need a sim change, make it small, keep `tests/sim.test.mjs` green, and say so in your report.

### Scoring and flock rules (FLOCK-1/2) — implemented in sim
Every egg: `eggs += 1`. Ordinary +10 pts. Golden +50 and hatches a duckling only while `flock < 5` (at 5 it still counts
as an egg and points). Shield absorbs the next hit/fall first, then one duckling, else the attempt ends (`status 'dead'`).
A survivable hit = knock-back + `T.invulnHit` recovery. A survivable fall = back to the latest checkpoint flag
(`respawn`). Retry after death restores the *saved* snapshot (totals as of the last save), see §7.

## 4. Level generation (`levelgen.mjs`)

```js
export function generateLevel({ chapter /*0..12*/, circuit /*1..*/, seed /*uint32*/ }) -> Level   // format: sim.mjs header
export function levelSeed(journeySeed, circuit, chapter) -> uint32                                  // mixSeed(...)
```
Pure + deterministic (`JSON.stringify` equal for equal inputs). Uses `rng.mjs`, `chapters.mjs`, `tuning.mjs`.
No `Math.random`, no `Date`.

**Structure (LEVEL-1).** Total main-route length = `chapters[i].seconds * T.cruise` (±6 %). Beats: *opening* (~22 %,
teaches or recalls the chapter's signature move — see `learn` in chapters.mjs — in isolation), *middle* (~53 %, varies
it, mixes in earlier chapters' moves in later chapters), *closing* (~25 %, a harder combination that leads to the gate
or the beacon). Cues (`level.cues`) give a short tip caption just before the first instance of a new thing
(e.g. ch1: "Swipe up to jump" ~250 u before the first gap).

**Difficulty (LEVEL-2).** Use `difficulty(chapter, circuit)` (0..20) to scale: gap widths (≤ `T.maxGapEasy` early →
≤ `T.maxGapHard`), landing widths (≥ `T.minLanding`), enemy count/speed, number of chained moves, crumble/lift/mover
timing, how much recovery room sits between hazards. Early chapters isolate one decision at a time; later chapters
combine skills, shorten safe timing windows (never below `T.minWindow` s), and ask for a second landing.

**Fairness rules (hard constraints, enforced by tests):**
1. First ≥ 700 u of every chapter has no hazard, enemy, or required jump. Chapter 1's first golden egg is on flat safe
   ground within its first 600 u; its first required gap comes after that, ≤ 46 u wide with a ≥ 160 u landing.
2. Every required jump is possible at the default cruise with one swipe: gap ≤ `min(T.maxGapHard, jumpDistance()-…)`,
   takeoff window ≥ `T.minWindow` seconds (compute analytically from `jumpDistance`, `coyote`, `edgeForgive`, landing
   height difference). Never require a swipe-right/left to make a jump (those are optional helpers; **ice chapters
   may require an early brake**).
3. A checkpoint flag sits on static *ground* (`kind:'ground'`) before every demanding sequence (≥ 350 u of safe ground
   after the flag before the next hazard, ≥ 250 u of safe ground before it). 4–8 flags per chapter, spacing ≤ 25 s.
   `checkpoints[0]` is the start (id 0). Each checkpoint names its `platform` id.
4. Every required landing and every hazard on the main route is on screen ≥ 1.2 s before it matters (nothing the
   player must read is within 300 u of the camera's left edge, nothing is hidden by decoration — decoration lives in the
   renderer, so keep main-route platforms within y ∈ [150, 310] and give lifts/movers room).
5. Enemies on the main route: walkers patrol ≥ 90 u, speed ≤ 55 u/s (scaled), always with ≥ 120 u of flat ground beyond
   to land on after a stomp-hop or a jump-over; flyers only over ground, never over a required landing. Spikes: ≤ 60 u
   wide, with a ≥ 120 u ground approach.
6. Missing any egg never blocks completion. Golden eggs: ≥ 2 on/near the main route (reachable on safe ground or with
   one easy jump) + 1–3 "upper route" golden eggs rewarding harder jumps/springs. Ordinary eggs trace jump arcs over
   gaps, lines on the ground, and arcs over enemies. Shield (1–2/chapter from ch3) and magnet (0–1) pickups.
7. Beacon (ch 13): last thing in the level, on safe ground ≥ 300 u after the final hazard; `endX = beacon.x + 140`.
8. Circuits ≥ 2: fresh terrain (different seed → different arrangement), difficulty offset, everything still passes 1–7.

**Segment toolbox** (suggested; add more): flat run with egg trail; wide gap with egg arc; step-up/step-down islands;
stepping ledges over water (one-way thin `ledge`s); walker patrol (stomp or hop); spring pad to an upper ledge/golden egg
and back; crumble chain (`ledge` → `crumble` → `crumble`); flyer crossing; gap-then-spikes chain with recovery island;
cycling spikes; vertical lift to a high ledge; horizontal mover between islands; lift → crumble transfer; ice run with
gaps (long stopping distance); broken-span bridge (islands with gaps and tricky second landings); summit ascent
combining springs, lifts and timed jumps.

**Platform vocabulary reminder:** `ground` islands are thick (`h` 90–140, drawn to the bottom of the frame by the
terrain art) and solid at the sides; `ledge`/`crumble`/`lift`/`mover` are thin one-way slabs (`h` 14–18). `ice:true`
makes any of them slippery. Moving platform `amp` ≤ 90, `period` 3.2–6 s. Lifts/movers are ≥ 150 u wide (she keeps
rolling while she rides). Everything is sorted by `x`. All ids unique per array.

**Validation (tests/levels.test.mjs + tests/bot.mjs):** a look-ahead *planner bot* plays the real `sim` using only the
actions a thumb has (`jump`, `brake`, `push`, ≥ 0.15 s apart) by cloning the game (`cloneGame`) and searching
short action sequences. Required: for every chapter 0..12, circuits 1..3, ≥ 5 seeds each:
(a) the bot finishes with **zero hits and zero falls**; (b) a *human-noise* bot (reaction latency 80 ms + ±50 ms
jitter on each action) finishes without ever dying in ≥ 90 % of runs; (c) the clean main-route time at default cruise
(jump-only, no push) lies inside `paceBand(chapter)` and within ±12 % of `chapters[i].seconds`;
(d) determinism; (e) fairness rules 1–7 checked statically; (f) save/restore at each checkpoint continues correctly.

## 5. Art (ACTORS, TERRAIN)

Read `artkit.mjs` and `/home/user/benlambm/egg-runner-2/js/art.js` (the reference object art: warm upper-left light,
colored outlines, rounded volume, contact shadows; cloned read-only at that path, commit e0c5fa9). Port the *look*, not
the code. Pictures are drawn in world units, origin = ground contact point (feet / bottom-centre), through
`SpriteCache` (draw once per variant/frame at the current scale, stamp every frame). Drawing is vector (paths,
gradients) — smooth at full phone resolution (DPR 3). Never `imageSmoothingEnabled = false` for sprites.

**ART-2 legibility** (checked visually in bright Meadow, misty Fogwood, dark Lantern Caverns):
* ordinary egg: small cream oval with a few speckles, gentle bob. golden egg: bigger, golden, with a glow halo
  and a pulsing 4-point star sparkle, a different silhouette (slight point/crown) and a bouncier motion.
* safe ground: solid slab, grass/stone cap with rim light. crumbling ledge: visibly cracked (fracture lines, chipped
  lumps, dashed lower edge), shakes when `state==='rumble'`, chunks fall when `fall`. Never just a colour change.
* duckling follower: small yellow chick with orange bill, waddles/hops. Pickups: shield = round blue shell badge with
  rim; magnet = red U-magnet with silver tips. They must never be confused with a duckling.
* In dark chapters (`chapter.dark`) platforms and creatures get a bright rim light + a soft glow so they pop.
* Every drawn thing has a clear dark-ish own-hue outline; contrast against its background ≥ ~3:1 at phone size.

**ACTORS exports** (`art-actors.mjs`) — all take `(ctx, cache, params)`; ctx already has the world transform; `t` = seconds:
```
drawMama(ctx, cache, { x, y, face, vx, phase, onGround, vy, squash, hurt /*0..1*/, invulnFlash /*bool*/, shield /*bool*/, happy /*bool: beacon*/, t, rock /*radians, precomputed by renderer or 0*/ })
drawDuckling(ctx, cache, { x, y, face, air /*bool*/, t, i /*phase offset*/, alpha })
drawEgg(ctx, cache, { x, y, kind: 'egg'|'gold', t, i })           // x,y = centre; bob inside
drawHatchBurst(ctx, cache, { x, y, progress /*0..1*/ })           // golden egg cracks, duckling pops out (0.9 s)
drawWalker(ctx, cache, { species, palette, x, y, face, t, squash /*0..1 when stomped*/ })      // snail|caterpillar|beetle|crab|mite
drawFlyer(ctx, cache, { species, palette, x, y, face, t })                                      // bee|moth|gull|bat|owl|hawk
drawShieldPickup / drawMagnetPickup(ctx, cache, { x, y, t })
drawShieldBubble(ctx, cache, { x, y, t, pop /*0..1*/ })           // bubble around Mama while shielded
drawFlag(ctx, cache, { x, y, active, t, palette })                // checkpoint flag
export const ACTOR_SIZES = { mama:{w,h}, … }                      // so the renderer can place shadows
```
Mama: a big, cream, egg-shaped mother with kind eyes (blink), rosy cheeks, tiny orange beak, little wings and feet,
a small head tuft/bonnet. Her shell *rocks* with her travel (rock angle ≈ `sin(phase*0.09) * 0.10 * speed factor`);
squash/stretch on jump/land; wince when hurt; joyful hop for `happy`. Hurtbox is 26×38 u; art ≈ 44 u tall.
Ducklings ≈ 20 u. Eggs ≈ 16×20 u; golden ≈ 22×28 u. Walkers 34×26, flyers 30×24.

```
drawPlatform(ctx, cache, p /*runtime platform*/, chapter, t)      // ground (thick, to y=T.killY), ledge, crumble (state!), lift, mover; ice flag; chapter.skin + palette
```

Ground islands: grass/stone cap with a lit rim, soil body with strata, rocks, tufts, a slightly irregular underside
fading into the dark at `T.killY` so pits read as drops. Skins per chapter in `chapters.mjs → skin`.

## 6. Renderer (SCENE) — `render.mjs`, `effects.mjs`

```js
export class Renderer {
  constructor(canvas)
  async load()                          // preload nothing heavy; bg images load lazily
  async preload(chapterIndex)           // resolves when that chapter's background is decoded
  resize(cssW, cssH, dpr, insets)       // updates scale/view; clears sprite cache if scale changed
  get view()                            // { w, h /*visible world units*/, scale /*css px per u*/, dpr }
  resetCamera(game)                     // snap camera to Mama
  spawn(events, game)                   // feed sim events -> particles/popups/captions/pill (visual only)
  showChapterCard(chapterIndex, circuit) // name + story cue, drawn small at the top, fades, never over the action band
  draw({ game, now, alpha, mode, reducedMotion, fade, paused })     // mode: 'title'|'play'|'paused'|'dead'|'finish'
}
```
Layer order (back → front): sky/bg painting (pixel-crisp, mirror-tiled, parallax 0.06–0.14 of camera, covers the whole
canvas incl. safe areas) → drifting atmosphere (clouds/mist/petals/snow/embers/fireflies, per `chapter.fx`; **fog and
mist are drawn BEHIND platforms and actors and never over the landing zone**) → water band → platforms → hazards,
springs, flags, gate/beacon → pickups → enemies → contact shadows → ducklings → Mama (+bubble) → front particles →
captions/popups/egg pill/chapter card (screen space). A required jump must never be hidden by scenery or UI.

*Contact shadow* (ART-1): soft ellipse on the nearest platform top below Mama (and ducklings, enemies), scaled and
faded with height (`1 → 0.45` over ~140 u), so she can judge her landing; also drawn under moving platforms' riders.
*Transient HUD only* (VIEW-3): no persistent score header. Show: floating `+10`/`+50` popups; an **egg pill**
(top-left, inside insets) that appears for ~2 s when the egg total changes; hatch/checkpoint/hit/tip captions in a
small band at the top-centre (y < 18 % of height, never over platforms); chapter card at chapter start; the flock is
shown *in the world* (followers). The pause button is a DOM button (SHELL) at top-right.
*Event VFX map:* egg → sparkle ring + pop; gold/hatch → shell-burst + star burst + `drawHatchBurst` + caption
"Duckling hatched! 3/5"; at 5 → "The flock is full! +50"; stomp → star puff + squashed enemy fade; spring → compress +
ring; land → dust; crumble → debris; hit → shake-free flash + feathers; duckling-lost → duckling flies off and fades;
shield → bubble pop; checkpoint → flag unfurl + sparkles + "Checkpoint saved" caption; beacon → big flare, light
rays, confetti; exit → fade. `reducedMotion`: no screen shake/zoom, rock amplitude ×0.25, fewer/slower particles.
Pausing freezes everything (draw uses `now` only for ambient loops; during `paused` ambient may continue slowly).

## 7. Save (SHELL) — `save.mjs` (pure; storage injected)

```js
SAVE_KEY = 'egg-mama-save-v2'; SETTINGS_KEY = 'egg-mama-settings-v1'
Save = { v: 2, journeySeed, circuit, chapter, checkpoint, eggs, score, flock, beacons /*lit count*/, reached: { circuit, chapter }, savedAt }
loadSave(storage) -> Save|null          // validates; migrates the legacy GitHub Pages save (below); never throws
writeSave(storage, save) / clearSave(storage)
newJourney(seed) -> Save                // circuit 1, chapter 0, checkpoint 0, eggs/score/flock 0
saveAt(prev, { circuit, chapter, checkpoint, carry:{eggs,score,flock}, beaconLit? }) -> Save
loadSettings(storage) -> { muted, tapToJump, best:{score,eggs}, seenHelp }  // + migrates legacy egg-hero-sound/best
writeSettings(storage, settings)
```
Autosave at: checkpoint flags (`checkpoint` event), chapter transitions (start of next chapter, checkpoint 0), and the
beacon (saves the start of the NEXT circuit's chapter 1 with `beacons+1`). **Continue** and **Retry checkpoint** load
the saved (circuit, chapter, checkpoint) → regenerate the level from `levelSeed(journeySeed, circuit, chapter)` →
`createGame(level, carry, {checkpoint})`. Failed attempt / reload / Main Title never clears the save. **Start Over**
(title only) asks for confirmation; Cancel keeps the save; Confirm → `newJourney(random seed)`, Meadow, zeros.
**Legacy migration (SAVE-2):** the previous release stored `localStorage['egg-hero-journey-v1'] = JSON.stringify({format:1,
state:{stage, generatedStage, ducklings, collected, points, beaconsLit, …}})`, plus `egg-hero-best`, `egg-hero-sound`
("off" = muted). Convert: `circuit = floor(stage/13)+1`, `chapter = stage % 13`, `checkpoint = 0`, `eggs = collected`,
`score = points`, `flock = ducklings (≤5)`, `beacons = beaconsLit`, new random `journeySeed`; keep the legacy key
untouched; the v2 key wins once it exists. Garbage/unknown data → `null`.

## 8. Input (SHELL) — `input.mjs`

```js
export function classifySwipe(dx, dy, surfaceHeight) -> 'jump'|'brake'|'push'|null       // pure, tested
export class Input { constructor(stage, { onAction(a), onPause(), onMute(), isActive() }); held:{left,right}; tapToJump; destroy() }
```
Pointer events on the stage; fire the action as soon as the drag passes the threshold (don't wait for release), once
per pointer. Both thumbs work independently (multi-pointer). Swipe up → `jump`, left → `brake`, right → `push`, down
→ nothing. A short low-movement tap = `jump` when `tapToJump` (default on, setting in the pause menu) so small
children can play; taps that start on UI controls (`[data-ui]`, buttons, menus) are ignored. Keyboard: A/←
and D/→ are *held* steering (`held`), Space/↑/W = jump (non-repeat), P/Esc = pause, M = mute. `isActive()` false → ignore
gestures. Prevent default on `touchmove` (non-passive), `gesturestart/change`, `contextmenu`, `selectstart`,
`dblclick` zoom; `touch-action:none` on the stage. No page scroll, no bounce, no pull-to-refresh.

## 9. Audio (AUDIO + MUSIC)

```js
export class GameAudio {
  constructor({ muted })
  unlock()                     // MUST be callable from a user-gesture handler; creates/resumes the AudioContext;
                               // sets navigator.audioSession.type = 'playback' when present (iOS silent switch)
  get muted(); setMuted(b)     // persisted by main via settings; muting silences music+sfx immediately
  playSong(id, { fade = 0.4 }) // id from music.mjs ('title','meadow',…,'beacon-summit','beacon'); no-op if already playing
  stopSong({ fade })
  sfx(name, opts)              // names below; safe before unlock/while muted
  handle(simEvent)             // maps sim events to sfx (jump, land, egg, gold→'goldHatch', …)
  suspend() / resume()         // app paused, tab hidden, rotated away: stop scheduling & suspend the context;
                               // resume: ONE scheduler only, song position kept (or restarted at loop start)
  dispose()
  renderOffline(id, seconds, sampleRate) -> Promise<AudioBuffer>     // test hook using OfflineAudioContext
}
```
SFX names: `egg, goldHatch, ducklingLost, checkpoint, beacon, jump, land, stomp, spring, hit, shield, shieldBreak,
magnet, crumble, fall, dead, chapter, ui, uiBack, steer`. The five required ones must be *distinguishable by ear*:
ordinary pickup (short bright blip, small pitch variation, rising on streaks), golden hatch (shell crack + rising
4-note chime + chick peep, ~0.9 s, bright 1–4 kHz, loud), lost duckling (descending sad peep + whoosh), checkpoint
(two-note flag flourish), lit beacon (big rising major arpeggio swell with shimmer, ~2.5 s). **Phone speakers have no
bass:** keep important cues' energy between 800 Hz and 5 kHz, give bass lines upper harmonics, high-pass the music
mix near 90 Hz. **Ducking:** on `goldHatch`, `beacon`, `checkpoint`, `ducklingLost` the music bus dips ~8–10 dB for
the cue's length then recovers, so a hatch is audible over the busiest section. Master compressor/limiter, no
clipping (peak < 0.98 in offline renders). Hidden tab / `pagehide` / `visibilitychange` / paused → `suspend()`.

**Music (`music.mjs`)**: `export const SONGS = { title, meadow, 'clover-mill', reedwater, orchard, 'amber-quarry', fogwood,
canyon, 'glass-coast', 'lantern-caverns', frostline, ridge, dawnbridge, 'beacon-summit', beacon }` (ids match
`chapters[i].song`; `beacon` is the fuller Meadow return played when the beacon lights and loops on the finish screen)
and `export const songFor(chapterIndex, circuit)`. Song data (an object, built with helper functions at import time):
```js
{ id, title, bpm, beatsPerBar: 4, stepsPerBeat: 4, bars,            // loop length = bars*beatsPerBar*stepsPerBeat steps (16th grid)
  swing: 0..0.5,                                                    // delays odd 16ths
  layers: [ { name, inst, vol, pan, fx?: { delay?:{beats,feedback,mix}, vibrato?:{rate,depth,delaySteps}, filter?:{type,freq,q} },
              play?: [[barFrom, barTo], …],                          // bars (end exclusive) where the layer is audible: builds/drops
              notes?: [[step, midi, lenSteps, vel?], …],             // melodic
              hits?:  [[step, 'k'|'s'|'h'|'o'|'t'|'c'|'r'|'sh'|'cl', vel?], …] } ] }   // drums, inst:'kit'
```
Instruments the engine must provide (closed list): `pulse12 pulse25 pulse50 tri saw sawLead bell marimba pluck pad
bassTri bassPulse bassSaw kit`. Loops must be *seamless* (the scheduler is sample-accurate from `AudioContext.currentTime`;
note tails may ring over the seam). The Meadow theme is a short hummable 4-bar phrase (diatonic, stepwise-with-a-leap,
≈ C major pentatonic flavour, ~120–128 bpm) over a buoyant bouncing bass and crisp percussion, **leaving gaps for
pickup sounds**; it returns, developed, in every chapter (new key/mode/tempo/instrumentation/rhythm, same recognisable
contour), and as a full, triumphant arrangement in `beacon`. Each chapter song is ≥ 48 s per loop (32 bars at 160 bpm
= 48 s; prefer 56–90 s, slower tempos need fewer bars) with A/B/A′ development so a 2-minute chapter doesn't feel looped.
Mood map: valley (meadow/mill/reedwater/orchard) bright & bouncy; quarry/fogwood/canyon driving, sparser, minor touches;
glass coast sunny shuffle; caverns echoing crystalline (bell/pluck + long delay), mysterious but not scary; frostline
glittering and cool; moonridge nocturne with steady pulse; dawnbridge warm swell; summit the ascent — rising, building
to the beacon return.

## 11. Main loop (INTEGRATE) — `main.mjs`

States: `boot → title → playing ⇄ paused | rotate → dead | transition | finish`. Fixed-timestep accumulator (`T.step`),
drop time beyond `T.maxFrame`; `requestAnimationFrame` for drawing with `alpha`. Hidden tab / blur / `pagehide` / rotate
→ pause + `audio.suspend()`. Title: a live scene of the saved chapter at its checkpoint (Mama idle with her flock),
music `title`. Play: `startRun` → ease-in. Chapter end: `exit` event → save next chapter start → fade → next level, card
with story cue → `startRun`. Death: after `T.deadSeconds` show `dead`; Retry reloads the saved snapshot. Beacon: music
`beacon`, caption, after ~2.5 s show `finish`; Keep Going → circuit+1 chapter 0 (carry flock/eggs/score), saved.
Settings (muted, tapToJump, best) persisted. Service worker registered after load.

## 12. Testing, tooling, conventions

* `node --test` runs everything in `tests/*.test.mjs` (pure logic; must pass in < 3 min total).
* Playwright (already installed globally; Chromium at `/opt/pw-browsers`; `require('playwright')` works — **do not**
  install anything; launch with `chromium.launch()` and device emulation e.g. iPhone 13 landscape 844×390, Pixel 7
  landscape 915×412, small 640×300 with toolbar) lives in `tests/e2e/*.mjs`. Screenshots go to the session scratchpad, never the repo.
  Serve `docs/` with `python3 -m http.server`. Pass `--trace off` if using @playwright/test.
* Code style: ES modules, 2-space indent, no frameworks, no TypeScript, small pure functions, comments that explain *why*.
  Every tunable number goes in `tuning.mjs` (or a clearly commented const at the top of the module for purely cosmetic numbers).
* Never add a network call, web font, CDN script, analytics or an image asset for game objects. Backgrounds stay exactly as they are.
* Do not edit files you do not own except for tiny, reported fixes. Report API deviations explicitly.
