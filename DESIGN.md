# Egg Mama — design contract

The product spec is `SPEC.md` (requirement IDs VIEW-1, INPUT-1, FLOCK-1, … are quoted below). This file is the
engineering contract that lets many people build modules in parallel and have them fit. **Read `SPEC.md` first.**

## 0. Pillars (why the old build failed and what we do instead)

The old build was a *website that contained a game*: masthead, score header, button footer, page scroll. This one is a
*game that happens to run in a browser*:

* **One fixed, full-viewport stage.** `html, body` are locked (no scrolling, no bounce, no pull-to-refresh, no
  zoom). A single `<canvas>` fills the visual viewport. Everything — world, HUD, captions — is drawn into that canvas or
  layered *inside the same stage* as DOM overlays (menus). Nothing ever resizes or moves the canvas.
* **One continuous world, about an hour long.** No level select, no gates, no load screens between landscapes:
  the 13 painted landscapes dissolve slowly into one another as Mama rolls on, the painted background drifts by very
  slowly behind her (`T.backgroundParallax`), and Mama is always rolling forward (she can only brake / back up
  briefly). One whole circuit — Meadow to the beacon — takes ~59 minutes (`JOURNEY_SECONDS` in chapters.mjs; each
  landscape 3½–5⅓ minutes). The difficulty curve is *slow*: `difficulty()` rises from 0 to ~11 across the whole hour, so
  every minute is only a hair harder than the last. After the beacon the world rotates back to a fresh Meadow
  (circuit 2, difficulty starts ~4.5) and keeps going. This **replaces** the spec's proposed 60–150 s chapter bands
  (SPEC says they are "a first pass… adjust after real players"; the product owner asked for ~1 h).
* **Landscape phone first.** Fixed world height (360 u). Wider screens show more world sideways, never more vertically.
* **Touch first.** Swipe up = jump, left = brake/back up, right = push ahead. One swipe = one action.
* **Backgrounds are the only pixel art.** The 13 `docs/assets/*.webp` paintings are drawn crisp (smoothing off).
  Everything the player touches is smooth vector art drawn in code (no image assets for objects).
* **Everything deterministic.** Level = f(journeySeed, circuit, chapter). Sim = f(level, inputs).
* **No build step, no dependencies, no network calls while playing.** Plain ES modules in `docs/` (GitHub Pages serves
  `docs/` from `main`). Works offline after first load (service worker). All relative URLs (served from a repo subpath).

## 2. Units, view and camera

* World unit `u`; y DOWN. `T.viewH = 360` always visible vertically. Ground baseline `T.groundY = 292`. Nothing the
  player must do happens above y = 40. No vertical camera movement at all (the horizon stays steady in a jump).
* Screen mapping (render.mjs): `scale = cssH / 360` (CSS px per u) normally; if `cssW / scale < T.viewMinW (560)` use
  `scale = cssW / 560` and show extra sky above (world bottom stays anchored to the bottom edge). Visible world width
  is `cssW / scale` (≈ 640 on 16:9, ≈ 780 on 19.5:9). Draw the canvas at `dpr` (cap 3, cap pixels ≈ 3.6 M).
* Camera x: Mama at `T.mamaScreenX` (30 %) of the width, plus a little lead while pushing, smoothed; clamped to the
  chapter (`start.x - 120 … endX + 260`). Snap on chapter start/respawn. Camera never leads a jump differently.
* Background: the pixel painting of the current landscape, cover-fitted to the whole canvas (crisp, smoothing off),
  drifting at `T.backgroundParallax` of the camera (so a ~4-minute landscape slides by about one screen's width), mirror-tiled if
  it ever runs out. Around each landscape boundary (`level.chapters[k].x0 ± T.blendHalf` u) the next painting dissolves in
  (smoothstep alpha). Palettes, weather (`chapter.fx`), fog and music follow the same dissolve; platforms keep the skin of
  the landscape they were generated for (`platform.ch`).
* Safe areas: `insets {top,right,bottom,left}` in CSS px (from `env(safe-area-inset-*)`). Scenery draws to the full
  canvas edges; anything the player must tap or read (pause button, captions, egg pill) stays inside the insets.

## 3. Simulation (`sim.mjs` — already written; read its header)

`createGame(level, carry, {checkpoint})`, `startRun`, `easeIn` (after pause/rotation), `act(game,'jump'|'brake'|'push')`,
`step(game, {left,right})` at fixed `T.step = 1/120`, `drainEvents`, `respawn`, `snapshotCarry`, `cloneGame`,
and pure helpers `platformPosAt`, `enemyPosAt`, `hazardActive`, `hazardWarn`. Runtime state the renderer reads:
`game.mama {x,y,px,py,vx,vy,onGround,face,phase,squash,hurtT,invuln,…}`, `game.followers[]`, `game.platforms[]`
(`cx,cy` current top-left; `state` idle|rumble|fall for crumble), `game.pickups[]` (`taken`), `game.enemies[]`
(`x,y,face,defeated,defeatT`), `game.springs[]` (`bounceT`), `game.shield`, `game.magnet`, `game.flock`, `game.eggs`,
`game.score`, `game.checkpoint`, `game.status` (`ready|running|dead|exit|beacon`), `game.statusT`, `game.t`.
Interpolate drawing with `alpha` between `px,py` and `x,y` (and followers' `px,py`). Evaluate moving things at
`t - (1-alpha)*T.step` using `platformPosAt/enemyPosAt` or just use `cx,cy,x,y` (crumbles use `cy`).

If you need a sim change, make it small, keep `tests/sim.test.mjs` green, and say so in your report.

### Scoring and flock rules (FLOCK-1/2) — implemented in sim
Every egg: `eggs += 1`. Ordinary +10 pts. Golden +50 and hatches a duckling only while `flock < 5` (at 5 it still counts
as an egg and points). Shield absorbs the next hit/fall first, then one duckling, else the attempt ends (`status 'dead'`).
A survivable hit = knock-back + `T.invulnHit` recovery. A survivable fall = back to the latest checkpoint flag
(`respawn`). Retry after death restores the *saved* snapshot (totals as of the last save), see §7.

## 4. World generation (`levelgen.mjs`)

```js
export function generateLevel({ circuit /*1..*/, seed /*uint32*/ }) -> Level      // ONE world = a whole circuit (format: sim.mjs header)
export function levelSeed(journeySeed, circuit) -> uint32                           // mixSeed(...)
export function generateChapter?(...)                                               // optional internal helper(s); landscapes use mixSeed(seed, chapterIndex)
```
Pure + deterministic (`JSON.stringify` equal for equal inputs). Uses `rng.mjs`, `chapters.mjs`, `tuning.mjs`. No
`Math.random`, no `Date`. Generation of the full ~390 000 u circuit must take < 150 ms in Node (phones are ~3× slower)
and the data must stay compact (a few MB at most). The renderer culls with a binary search over x-sorted arrays, so
**every array is sorted by x** (platforms by `x`, pickups/enemies/hazards/springs by their x / x0 / cx, checkpoints by x)
and ids are unique and equal to the array index.

**Length and pacing (the main-route "clean time" = jump-only at default cruise, no push, excluding pauses/retries):**
landscape *i* spans `chapters[i].seconds * T.cruise` u (≈ 24 000 – 35 000 u) ± `T.paceTolerance` (`paceBand(i)`); the whole
circuit is `JOURNEY_SECONDS` ≈ 59 min and must land in `T.journeyMinutes`. `level.chapters` (contiguous, sorted) records each
landscape's x range and the id of its first flag; platforms carry `ch`; checkpoints carry `ch`. Every landscape begins on a
long safe island with a flag, a quiet stretch (≥ 700 u without hazards) and its story cue; the join between landscapes
is a normal, easy, safe stretch of ground (no gate, no pause) — the dissolve happens over it.

**Structure of one landscape (3½–5⅓ minutes must *hold a child's attention*):** about 7 **acts**, each a
small arc with its own character (measured over 16 000 acts: recall ≈ 28 s, teach / vary / combine ≈ 45 s, breather ≈ 15 s,
closing ≈ 20 s, the set piece ≈ 60 s and never over 85 s): *recall* (easy re-use of what she already knows), *teach* (the landscape's signature
move, isolated — see `learn`), *vary*, *combine*, a **breather** (egg field / scenic stretch / flock moment — no hazards,
15–25 s, a flag), a **set piece** (a memorable, hand-composed-feeling sequence unique to the landscape: the windmill
yard, the floating-logs run, the quarry crane, the moth lanterns, the canyon spike run, the cliff lifts, the crystal
descent, the ice slide, the moon bridge, the broken bridge, the summit climb) and a **closing** challenge that eases into
the next landscape. Difficulty inside a landscape is a gentle *sawtooth on a slow ramp*: each act peaks slightly above
the last, each breather relaxes, and the baseline across the hour is `levelDifficulty(chapter, circuit, within)` (`levels/params.mjs`: 0 → ~11 in circuit 1, see rule 8).
Variety comes from many segment variants, seeded randomisation of widths/heights/spacing, optional **upper routes** with
golden eggs (harder jumps, springs, riskier timing), **treasure caches**, shield/magnet pickups, and story captions
(`level.cues`: the landscape's `story` near its start, each `chapter.trail` line at its `at` fraction, plus tips just
before the first appearance of each new element — e.g. 'Swipe up to jump' ~250 u before Meadow's first gap).
No two consecutive acts may use the same segment template; keep a ring buffer of recent templates.

**Difficulty (LEVEL-2), slowly.** Scale from `levelDifficulty()`: gap widths (≤ `T.maxGapEasy` → `T.maxGapHard`), landing
widths (≥ `T.minLanding`), enemy count/speed, chained moves, crumble/lift/mover timing, recovery room between hazards. A
landscape's *new* element is introduced alone, at low intensity, repeated with growing intensity across several acts before
it is combined with others. Early landscapes isolate one decision at a time; later ones combine skills, shorten safe
timing windows (never below `T.minWindow` s; in practice no required hop or spike has a model window under 0.36 s, which is
≥ 0.30 s measured in the sim) and ask for a planned second landing. **Nothing may feel like a difficulty
jump at a landscape boundary**: the first act of landscape *i+1* is at most ~1 difficulty point above the last act of *i*.

**The felt ramp: the pacing controller (LEVELS-2/3).** Difficulty `d` shapes *how hard* an event is; the controller shapes *how
many* a minute. `params.RATE(i, within, circuit)` is a table of **threat-weighted required events a minute** per landscape, rising
from ≈ 5.3 in Meadow to ≈ 11 at the Summit (a hop, a wall, a lift or mover board and exit, a walker and a static spike count 1; see
*threat weights* below). `levelgen` turns a landscape's rate into a quota of events for each act (shared by weight and
`ROLE_RATE`: recall and closing a little calmer, set piece and combine a little busier), and `acts.mjs` spaces the events: the next
one is due at `x0 + (events so far + ½) * per`, the first rest of every spec is as long as it takes to land there, and
`tryOrder()` picks WHICH spec by variety (no beat above a quarter of a landscape; the landscape's own element is favoured most in its
teaching act, `OWN_BONUS`), by how well the spec's events per length match the pace, by `params.chainCap` (singles early,
doubles, triples ... fives at the summit) and by starvation (≥ 1100 u without a required event: only a beat that has one will do). A
hard check in `runSpec` refuses a spec that would grow a chain (events less than ~3 s apart, counting the ones before) past 4
in the first six landscapes (7 later). The controller is a heuristic and its results are only ever judged from the BUILT
geometry (tests/felt.mjs), never from `RATE`.

*Threat weights.* A moth is something to READ, but a Mama who never jumps is hit by only about a third of the low ones and by no
high one she rolls under (25 of Fogwood's 28 events had been moths: 3.5 planner jumps a minute against 8.2 in Amber Quarry). So
an event counts what it really asks: `phys.flyerThreat` (the share of 24 game-clock phases at which an idle Mama rolling through
the flyer's zone is hit, with the sim's own overlap rule), a cycling spike the share of the time it is up, a spring that carries a
gap `SPRING_THREAT` 0.25 (she rolls on and flies), everything else 1. `tests/felt.mjs` measures the same thing independently
(finer, from the finished level), and the tests compare both with an idle Mama in the real sim. The ramp the tests assert is the
threat-weighted one; **the planner bot's jumps a minute** (a calm player's real actions) track it within 20 % in every landscape.
Fogwood's acts are now moths *and* mossy logs, gaps and cracked stones (a moth beat usually comes with a hop), Orchard's springs
carry gaps but its required route is hops, logs and branch steps.

*The definitions* (tests/felt.mjs documents each; the tests assert all of them): `density` = every required event of a landscape
per minute of its whole length (opening, join, breathers and flag stations included: what a child gets per minute of play);
`liveDensity` = only the live acts (no opening, join, breathers or stations); `liveInclDensity` = everything but breathers and
stations. Each exists raw and threat-weighted (`wDensity`, `wLiveDensity`, `wLiveInclDensity`). Measured (16 journeys, circuits 1-4):
the threat-weighted ramps have Spearman ≥ 0.95 and no landscape under 0.93 of the one before; the raw ones ≥ 0.90 and ≥ 0.91
(a moth and a spring are whole events there, so they ramp a little less cleanly: that is exactly why they are not the claim).

*The dead-stretch guard* (`levels/densify.mjs`). The controller's rests and the flag stations (600 u of guaranteed safe ground) leave a
tail in the distribution of the wait between two required events. After the circuit is built, any wait over 18 s (20 s in Meadow
and Clover Mill, 31 s where a breather act sits in it) gets one small hop CARVED into the flat ground between its events: a gap
taken out of a long island, ≥ 260 u of ground each side, ≥ 3 s from every other event, clear of every flag's safe zone, the
opening (860 u), the join (400 u), optional ledges and arcs of eggs, and a window checked with `trainFeasible` (≥ 0.42 s); nothing
else moves. Measured: no run waits over 26 s for a required event in any landscape (it was 2.8-3.3 % of runs, 32 % in Clover Mill),
the p90 of the waits is under 18.5 s everywhere.

*Circuits saturate.* `levelDifficulty` is chapters.difficulty() in circuit 1 (0 → ~11), the same 4.5 higher in circuit 2, and from
circuit 3 on EXACTLY circuit 2's ramp, capped at `D_MAX` 16: a child who reaches circuit 3 has played two hours and still
starts as gently as circuit 2's Meadow, and no window ever drops below the floor in any circuit (tested for circuits 1-6, 7, 12,
20, 99, 1000 and 4096). What grows is only the number of events a minute, a little and with diminishing returns (`circuitRate`:
+0.8 in circuit 2, up to +0.9 more by the Summit, never beyond that).

**Fairness rules (hard constraints, enforced by tests):**
1. The first ≥ 900 u of the world and the first ≥ 700 u of every landscape have no hazard, enemy, or required jump.
   Meadow's first golden egg is on flat safe ground within its first 700 u; its first required gap comes after that,
   ≤ 46 u wide with a ≥ 160 u landing, preceded by the tip caption. The first-appearance captions (`level.cues`, kind `tip`)
   also cover the first **wall** of a journey (a rise with no gap in front of it, where Mama stops dead until she is swiped up:
   walls are rare, about 1 a landscape, and a rise is otherwise a small hop).
2. Every required jump is possible at the default cruise with one swipe: gap ≤ `min(T.maxGapHard, jumpDistance()-…)`, takeoff
   window ≥ `T.minWindow` seconds (compute from `jumpDistance`, `coyote`, `edgeForgive`, landing height difference).
   Swipe-right/left are optional helpers, never required. (Ice is slippery — Mama is slow to speed up and slow to slow down — but
   in the sim it never enables a jump or a stop that plain ground does not: a push only helps a jump if it is issued within ~0.6 s
   before the takeoff or ~0.25 s into the air, braking is never rewarded, and the Frostline words say so; the optional
   ice and spring-steering beats below are where a swipe pays.)
3. A checkpoint flag sits on static *ground* (`kind:'ground'`) before every demanding sequence (≥ 350 u of safe ground
   after the flag before the next hazard, ≥ 250 u of safe ground before it) and at least every 35 s of main-route time.
   Flags are numbered by x; `checkpoints[0]` is the world start; `chapters[k].flag` is the flag that opens landscape k;
   each checkpoint names its `platform` id and `ch`.
4. Every required landing and every hazard on the main route is on screen ≥ 1.2 s before it matters (nothing the player
   must read within 300 u of the camera's left edge; main-route platforms stay within y ∈ [150, 310]; lifts/movers have room).
5. Enemies on the main route: walkers patrol ≥ 90 u, speed ≤ 55 u/s (scaled), with ≥ 120 u of flat ground beyond to land on;
   flyers only over ground, never over a required landing. Spikes are 7–8 u wide (takeoff window 0.43–0.44 s in the sim, against
   0.45–0.57 s for the median gap hop; the art is drawn much bigger than the hitbox on purpose) with a ≥ 120 u approach and ≥ 250 u of
   room after a landing in the first two spike landscapes. A clumsy small child (120 ms of unnoticed latency, ±120 ms of jitter)
   clears ≥ 88 % of Ember Canyon's segments (62 % with 14 u thorns), nothing under 83 %.
6. Missing any egg never blocks completion. Golden eggs: roughly one per 40–60 s on/near the main route (≥ 5 per
   landscape reachable with at most one easy jump) + upper-route golden eggs (1–3 per act sequence) for harder jumps/springs.
   Ordinary eggs trace jump arcs over gaps, lines on the ground, arcs over enemies (traced from the real parabola).
   Shield (from the 3rd landscape on, ~1 per 90 s) and magnet (~1 per 3 min) pickups.
7. The beacon (landscape 13) is last, on safe ground ≥ 300 u after the final hazard; `endX = beacon.x + 140`; `level.beacon` set.
8. Circuits ≥ 2: fresh terrain (different seed, different arrangement of templates), difficulty +4.5 in circuit 2 and then
   NO harder (the ramp saturates at circuit 2's, `D_MAX` 16; only the events a minute grow, a little: `circuitRate`);
   everything still passes 1–7, in circuits 1–6 and a few huge ones.

**Segment toolbox** (suggested; add many more variants — a 59-minute game needs dozens of templates): flat run with egg trail;
wide gap with egg arc; step-up/down islands; stepping ledges over water; walker patrol (stomp or hop); spring pad to an
upper ledge/golden egg and back; crumble chain; flyer crossing; gap-then-spikes chain with recovery island; cycling spikes;
vertical lift to a high ledge; horizontal mover between islands; lift → crumble transfer; ice run with gaps; broken-span
bridge; summit ascent combining springs, lifts, timed jumps; breathers (egg field, gentle rolling hills of low ledges,
flock moment); treasure alcoves; optional **steering** sequences above an unbroken main route (`iceLeap`: a ~112 u leap that a
push just before the edge carries; `springBrake` / `springPush` / `iceSpring`: a spring fixes where she takes off, so only a swipe
in the air reaches the ledge) — never required, golden eggs for good steering.

**Platform vocabulary:** `ground` islands are thick (`h` 90–140, drawn to the bottom of the frame) and solid at the sides;
`ledge`/`crumble`/`lift`/`mover` are thin one-way slabs (`h` 14–18). `ice:true` makes any of them slippery. Moving platform
`amp` ≤ 90, `period` 3.2–6 s. Lifts/movers are ≥ 150 u wide (she keeps rolling while she rides).

**Validation (tests/levels.test.mjs + tests/bot.mjs + tests/felt.mjs):** a look-ahead *planner bot* plays the real `sim` using only the
actions a thumb has (`jump`, `brake`, `push`, ≥ 0.15 s apart) by cloning the game (`cloneGame`) and searching short action
sequences. Because a circuit is an hour of play, verify **segment by segment**: for every pair of consecutive flags (all
~130-170 segments of a circuit; default test run samples a spread, `FULL=1` does all) start `createGame(level, carry,
{checkpoint:i})` and require: (a) the planner bot reaches flag i+1 with **zero hits and zero falls**; (b) a *human-noise*
bot (80 ms latency, ±50 ms jitter) does so without dying in ≥ 90 % of runs; (c) summing segment clean-times
(allowSteer:false) gives each landscape within `paceBand(i)` and the circuit within `T.journeyMinutes`; (d) determinism and
generation time (< 150 ms cold, ~30 ms warm); (e) rules 1–7 checked statically (and rule 8 for circuits 1-4, 1-6 under FULL); (f)
restoring at every flag works; (g)
difficulty never jumps across a landscape boundary (compare a computed per-act demand score; worst measured join 3.6 points, asserted 3.8);
(h) variety: no template repeats back-to-back and each landscape's signature element is present with the right intensity
progression. The **felt** measures (tests/felt.mjs, read from the finished geometry only, never from a generator curve):
(A) the threat-weighted and raw event ramps with and without the opening, join, breathers and stations (definitions above),
chains lengthening, windows shrinking, simultaneous demands, and **the planner's jumps a minute**; **the threat model** against an
idle Mama in the real sim, beat by beat; (B) no dead stretches (no run over 26 s, p90 ≤ 18.5 s, per landscape) and the carved
hops' placement; (C) variety (no beat above a third of a landscape, no geometry fingerprint above ~40 % from Clover Mill on,
Dawnbridge's plain hops ≤ 72 % in circuit 1, lifts ≤ 34 % of the Summit's events) and walls; (D) the optional ice and
spring-steering sequences need a swipe and are never required, and the push timing windows pin the Frostline words; (E)
imperfect players per landscape: a button-masher (no plan), a sloppy bot (80 ms, ±80 ms) and a clumsy child (120 ms, ±120 ms);
(F) takeoff windows MEASURED in the real sim for circuits 1-4 (hops ≥ 0.30 s, spikes ≥ 0.40 s). The windows, the dead-stretch
tail, the ramps and the floors are also checked for circuits 1-6 and a few huge circuit numbers.

## 5. Art (ACTORS, TERRAIN)

Read `artkit.mjs` and `/home/user/benlambm/egg-runner-2/js/art.js` (the reference object art: warm upper-left light,
colored outlines, rounded volume, contact shadows; cloned read-only at that path, commit e0c5fa9). Port the *look*, not
the code. Pictures are drawn in world units, origin = ground contact point (feet / bottom-centre), through
`SpriteCache` (draw once per variant/frame at the current scale, stamp every frame). Drawing is vector (paths,
gradients) — smooth at full phone resolution (DPR 3). Never `imageSmoothingEnabled = false` for sprites.

**ART-2 legibility** (checked visually in bright Meadow, misty Fogwood, dark Lantern Caverns):
* ordinary egg: small cream oval with a few speckles, gentle bob. golden egg: bigger, golden, with a glow halo
  and a pulsing 4-point star sparkle, a different silhouette (slight point/crown) and a bouncier motion.
* safe ground: solid slab, grass/stone cap with rim light. crumbling ledge: visibly cracked (fracture lines, chipped
  lumps, dashed lower edge), shakes when `state==='rumble'`, chunks fall when `fall`. Never just a colour change.
* duckling follower: small yellow chick with orange bill, waddles/hops. Pickups: shield = round blue shell badge with
  rim; magnet = red U-magnet with silver tips. They must never be confused with a duckling.
* In dark chapters (`chapter.dark`) platforms and creatures get a bright rim light + a soft glow so they pop.
* Every drawn thing has a clear dark-ish own-hue outline; contrast against its background ≥ ~3:1 at phone size.

**ACTORS exports** (`art-actors.mjs`) — all take `(ctx, cache, params)`; ctx already has the world transform; `t` = seconds:
```
drawMama(ctx, cache, { x, y, face, vx, phase, onGround, vy, squash, hurt /*0..1*/, invulnFlash /*bool*/, shield /*bool*/, happy /*bool: beacon*/, t, rock /*radians, precomputed by renderer or 0*/ })
drawDuckling(ctx, cache, { x, y, face, air /*bool*/, t, i /*phase offset*/, alpha })
drawEgg(ctx, cache, { x, y, kind: 'egg'|'gold', t, i })           // x,y = centre; bob inside
drawHatchBurst(ctx, cache, { x, y, progress /*0..1*/ })           // golden egg cracks, duckling pops out (0.9 s)
drawWalker(ctx, cache, { species, palette, x, y, face, t, squash /*0..1 when stomped*/ })      // snail|caterpillar|beetle|crab|mite
drawFlyer(ctx, cache, { species, palette, x, y, face, t })                                      // bee|moth|gull|bat|owl|hawk
drawShieldPickup / drawMagnetPickup(ctx, cache, { x, y, t })
drawShieldBubble(ctx, cache, { x, y, t, pop /*0..1*/ })           // bubble around Mama while shielded
drawFlag(ctx, cache, { x, y, active, t, palette })                // checkpoint flag
export const ACTOR_SIZES = { mama:{w,h}, … }                      // so the renderer can place shadows
```
Mama: a big, cream, egg-shaped mother with kind eyes (blink), rosy cheeks, tiny orange beak, little wings and feet,
a small head tuft/bonnet. Her shell *rocks* with her travel (rock angle ≈ `sin(phase*0.09) * 0.10 * speed factor`);
squash/stretch on jump/land; wince when hurt; joyful hop for `happy`. Hurtbox is 26×38 u; art ≈ 44 u tall.
Ducklings ≈ 20 u. Eggs ≈ 16×20 u; golden ≈ 22×28 u. Walkers 34×26, flyers 30×24.

## 6. Renderer (SCENE) — `render.mjs`, `effects.mjs`

```js
export class Renderer {
  constructor(canvas)
  async load()                          // preload nothing heavy; bg images load lazily
  async preload(chapterIndex)           // resolves when that chapter's background is decoded
  resize(cssW, cssH, dpr, insets)       // updates scale/view; clears sprite cache if scale changed
  get view()                            // { w, h /*visible world units*/, scale /*css px per u*/, dpr }
  resetCamera(game)                     // snap camera to Mama
  spawn(events, game)                   // feed sim events -> particles/popups/captions/pill (visual only)
  // (no chapter cards: landscape names / story cues arrive as 'chapter-enter' and 'cue' events through spawn())
  draw({ game, now, alpha, mode, reducedMotion, fade, paused })     // mode: 'title'|'play'|'paused'|'dead'|'finish'
}
```
Layer order (back → front): sky/bg painting (pixel-crisp, mirror-tiled, parallax 0.06–0.14 of camera, covers the whole
canvas incl. safe areas) → drifting atmosphere (clouds/mist/petals/snow/embers/fireflies, per `chapter.fx`; **fog and
mist are drawn BEHIND platforms and actors and never over the landing zone**) → water band → platforms → hazards,
springs, flags, gate/beacon → pickups → enemies → contact shadows → ducklings → Mama (+bubble) → front particles →
captions/popups/egg pill/chapter card (screen space). A required jump must never be hidden by scenery or UI.

*Contact shadow* (ART-1): soft ellipse on the nearest platform top below Mama (and ducklings, enemies), scaled and
faded with height (`1 → 0.45` over ~140 u), so she can judge her landing; also drawn under moving platforms' riders.
*Culling:* the world has ~10⁴ platforms: binary-search the x-sorted arrays for the visible window (+ art padding and
mover amplitude); never iterate everything per frame. Compute the current landscape and dissolve alpha from Mama's x
(`chapterSlotAt`, `T.blendHalf`); keep the previous painting loaded for the dissolve; preload the next one a few thousand
units ahead (`preload`); only decode what's needed (memory!). When a 'chapter-enter' event arrives show a small caption
"Chapter 3 · Reedwater" (top-centre, fading) followed by the story cue as a subtitle.
*Transient HUD only* (VIEW-3): no persistent score header. Show: floating `+10`/`+50` popups; an **egg pill**
(top-left, inside insets) that appears for ~2 s when the egg total changes; hatch/checkpoint/hit/tip captions in a
small band at the top-centre (y < 18 % of height, never over platforms); chapter card at chapter start; the flock is
shown *in the world* (followers). The pause button is a DOM button (SHELL) at top-right.
*Event VFX map:* egg → sparkle ring + pop; gold/hatch → shell-burst + star burst + `drawHatchBurst` + caption
"Duckling hatched! 3/5"; at 5 → "The flock is full! +50"; stomp → star puff + squashed enemy fade; spring → compress +
ring; land → dust; crumble → debris; hit → shake-free flash + feathers; duckling-lost → duckling flies off and fades;
shield → bubble pop; checkpoint → flag unfurl + sparkles + "Checkpoint saved" caption; beacon → big flare, light
rays, confetti; exit → fade. `reducedMotion`: no screen shake/zoom, rock amplitude ×0.25, fewer/slower particles.
Pausing freezes everything (draw uses `now` only for ambient loops; during `paused` ambient may continue slowly).

## 7. Save (SHELL) — `save.mjs` (pure; storage injected)


Autosave at: every checkpoint flag (`checkpoint` event), every landscape change (the flag that opens it — i.e. the same
mechanism: there is a flag at every landscape start), and the beacon (saves the start of the NEXT circuit, chapter 0 flag 0,
with `beacons+1`). **Continue** and **Retry checkpoint** load the saved (circuit, chapter, flag) → regenerate the world from

reload / Main Title never clears the save. **Start Over** (title only) asks for confirmation; Cancel keeps the save; Confirm →

`localStorage['egg-hero-journey-v1'] = JSON.stringify({format:1, state:{stage, generatedStage, ducklings, collected, points,
beaconsLit, …}})`, plus `egg-hero-best`, `egg-hero-sound` ("off" = muted). Convert: `circuit = floor(stage/13)+1`,
`chapter = stage % 13`, `flag = 0`, `eggs = collected`, `score = points`, `flock = ducklings (≤5)`, `beacons = beaconsLit`,

## 8. Input (SHELL) — `input.mjs`

```js

```

## 9. Audio (AUDIO + MUSIC)

```js
export class GameAudio {
  constructor({ muted })
  unlock()                     // MUST be callable from a user-gesture handler; creates/resumes the AudioContext;
                               // sets navigator.audioSession.type = 'playback' when present (iOS silent switch)
  get muted(); setMuted(b)     // persisted by main via settings; muting silences music+sfx immediately
  playSong(id, { fade = 0.4 }) // (main calls it when Mama is T.blendHalf/2 into a landscape; crossfade 3–4 s) id from music.mjs ('title','meadow',…,'beacon-summit','beacon'); no-op if already playing
  stopSong({ fade })
  sfx(name, opts)              // names below; safe before unlock/while muted
  handle(simEvent)             // maps sim events to sfx (jump, land, egg, gold→'goldHatch', …)
  suspend() / resume()         // app paused, tab hidden, rotated away: stop scheduling & suspend the context;
                               // resume: ONE scheduler only, song position kept (or restarted at loop start)
  dispose()
  renderOffline(id, seconds, sampleRate) -> Promise<AudioBuffer>     // test hook using OfflineAudioContext
}
```
SFX names: `egg, goldHatch, ducklingLost, checkpoint, beacon, jump, land, stomp, spring, hit, shield, shieldBreak,
magnet, crumble, fall, dead, chapter, ui, uiBack, steer`. The five required ones must be *distinguishable by ear*:
ordinary pickup (short bright blip, small pitch variation, rising on streaks), golden hatch (shell crack + rising
4-note chime + chick peep, ~0.9 s, bright 1–4 kHz, loud), lost duckling (descending sad peep + whoosh), checkpoint
(two-note flag flourish), lit beacon (big rising major arpeggio swell with shimmer, ~2.5 s). **Phone speakers have no
bass:** keep important cues' energy between 800 Hz and 5 kHz, give bass lines upper harmonics, high-pass the music
mix near 90 Hz. **Ducking:** on `goldHatch`, `beacon`, `checkpoint`, `ducklingLost` the music bus dips ~8–10 dB for
the cue's length then recovers, so a hatch is audible over the busiest section. Master compressor/limiter, no
clipping (peak < 0.98 in offline renders). Hidden tab / `pagehide` / `visibilitychange` / paused → `suspend()`.

**Music (`music.mjs`)**: `export const SONGS = { title, meadow, 'clover-mill', reedwater, orchard, 'amber-quarry', fogwood,
canyon, 'glass-coast', 'lantern-caverns', frostline, ridge, dawnbridge, 'beacon-summit', beacon }` (ids match
`chapters[i].song`; `beacon` is the fuller Meadow return played when the beacon lights and loops on the finish screen)
and `export const songFor(chapterIndex, circuit)`. Song data (an object, built with helper functions at import time):
```js
{ id, title, bpm, beatsPerBar: 4, stepsPerBeat: 4, bars,            // loop length = bars*beatsPerBar*stepsPerBeat steps (16th grid)
  swing: 0..0.5,                                                    // delays odd 16ths
  layers: [ { name, inst, vol, pan, fx?: { delay?:{beats,feedback,mix}, vibrato?:{rate,depth,delaySteps}, filter?:{type,freq,q} },
              play?: [[barFrom, barTo], …],                          // bars (end exclusive) where the layer is audible: builds/drops
              notes?: [[step, midi, lenSteps, vel?], …],             // melodic
              hits?:  [[step, 'k'|'s'|'h'|'o'|'t'|'c'|'r'|'sh'|'cl', vel?], …] } ] }   // drums, inst:'kit'
```
Instruments the engine must provide (closed list): `pulse12 pulse25 pulse50 tri saw sawLead bell marimba pluck pad
bassTri bassPulse bassSaw kit`. Loops must be *seamless* (the scheduler is sample-accurate from `AudioContext.currentTime`;
note tails may ring over the seam). The Meadow theme is a short hummable 4-bar phrase (diatonic, stepwise-with-a-leap,
≈ C major pentatonic flavour, ~120–128 bpm) over a buoyant bouncing bass and crisp percussion, **leaving gaps for
pickup sounds**; it returns, developed, in every chapter (new key/mode/tempo/instrumentation/rhythm, same recognisable
contour), and as a full, triumphant arrangement in `beacon`. Each landscape lasts 3½–5⅓ minutes, so each chapter song must be a LONG, developing loop: **≥ 100 s, aim 120–170 s**
(e.g. 64 bars at 120 bpm = 128 s) with A / B / A′ / bridge / breakdown / build development and layers entering and leaving, so a
player hears each song only ~2–3 times and it never feels like a short loop. `title` ≈ 40–60 s.
Mood map: valley (meadow/mill/reedwater/orchard) bright & bouncy; quarry/fogwood/canyon driving, sparser, minor touches;
glass coast sunny shuffle; caverns echoing crystalline (bell/pluck + long delay), mysterious but not scary; frostline
glittering and cool; moonridge nocturne with steady pulse; dawnbridge warm swell; summit the ascent — rising, building
to the beacon return.

## 11. Main loop (INTEGRATE) — `main.mjs`

States: `boot → title → playing ⇄ paused | rotate → dead | finish`. (No chapter-transition state: the world is continuous.)
Fixed-timestep accumulator (`T.step`), drop time beyond `T.maxFrame`; `requestAnimationFrame` for drawing with `alpha`.
Hidden tab / blur / `pagehide` / rotate → pause + `audio.suspend()`. Title: the live world at the saved flag (Mama idle with her
flock), music `title`. Play: `startRun` → ease-in. `checkpoint` event → autosave (`flagOf`); `chapter-enter` event → music
crossfade to that landscape's song + caption (the renderer handles the painted dissolve). Death: after `T.deadSeconds`
show `dead`; Retry rebuilds the game from the saved snapshot (same regenerated world). Beacon: music `beacon`, big
celebration, after ~2.5 s show `finish`; Keep Going → circuit+1 (new world, carry flock/eggs/score, saved) — a short
fade, then she rolls again; Main Title keeps the save (Continue then opens the next circuit's Meadow). Track `playSeconds`.
World generation happens off the critical path where possible (show the title scene immediately; generate the world for the
saved circuit during boot; < 150 ms in Node). Settings (muted, tapToJump, best) persisted. Service worker registered after load.

## 12. Testing, tooling, conventions

* `node --test` runs everything in `tests/*.test.mjs` (pure logic; must pass in < 3 min total).
* Playwright (already installed globally; Chromium at `/opt/pw-browsers`; `require('playwright')` works — **do not**

* Never add a network call, web font, CDN script, analytics or an image asset for game objects. Backgrounds stay exactly as they are.
* Do not edit files you do not own except for tiny, reported fixes. Report API deviations explicitly.
